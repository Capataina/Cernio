# Methodologies and Soft Skills

> Working-style patterns visible across the project portfolio. Derived from project files, not from CV-shaped self-description.

**Iterative, milestone-driven development with explicit exit criteria.** Every substantial project organises work as a numbered milestone sequence with per-milestone exit criteria, not as an open-ended backlog. NeuroDrive runs 11 milestones plus a Long-Term Plan and a Research Frontier; Nyquestro's roadmap is a 6-section architecture sequence (primitives → events → errors → hardening → matching → protocol → risk → strategy); Chrona's `plans/NNN_<topic>.md` 11-section schema (goal/scope, rejected alternatives, assumptions, interfaces/contracts, impacted areas, per-step incremental implementation with verification, testing/validation, risks, exit criteria, future considerations) is the strongest single example; Cernio's grading rubric has evolved across five named phases each driven by a concrete production failure; Vynapse's 10-milestone roadmap is encoded directly in the module tree as declarative scaffolding (16 deliberately-empty `.rs` files marked in `mod.rs`).

**Documentation-as-infrastructure / context-first iteration.** Documentation is treated as a load-bearing artefact, not an afterthought. Aurix carries a 1.16MB `context/` folder (14 system docs + 11 convention notes + 11 reference papers totalling ~17k lines, primary sources for the V3 math + LP-profitability + backtest-methodology literature) for a 79-file Rust backend; Cernio carries ~290KB of skill reference documentation explicitly framed as "the quality bar"; Consilium has 61KB of context docs against 89KB of source in a four-commit repo and a reusable `IMPLEMENT_NOW_*` execution-playbook template; the OSS-contributions umbrella holds 64 markdown notes (no third-party code) including per-repo `contribution-culture.md` + `repo-conventions.md` + dated `_issue-triage-YYYY-MM-DD.md`. The pattern is consistent enough to constitute a working style: write context before code, refer back during work, update afterwards.

**Test-driven validation for correctness-critical work.** Tests are written where correctness is load-bearing and skipped where verification is "reading and using the lesson". Cernio's 346-test suite (273 inline + 73 integration including 21 build-time `preferences_integrity.rs` invariants) directly surfaced three silent production bugs; Aurix has 30+ math tests as the most heavily-tested subsystem in the repo; Image Browser has 125 cargo lib tests + 62 vitest tests including a `cosine_topk_partial_sort_diagnostic.rs` integration test that pins the 2.53× speedup claim; Nyquestro pins byte-identical engine output across runs via `run_twice_identical_sequence_identical_output`; Performance Profiler's xUnit harness caught two production-crash bugs (BsonValue typing trap, `Channel.Reader.Count` macOS unsupported) before they shipped. Counter-examples (Tessarix has 0 tests, AsteroidsAI has ~2%) are paired with explicit framing — "verification is reading + using the lesson" or "audience widens later" — rather than oversight.

**Anti-puffing / honest current-state framing.** Every substantial project carries an explicit "Reality vs README" reconciliation. Aurix's `Gaps.md` lists 296 lines of acknowledged gaps; Nyquestro's `Gaps.md` states "the README describes the end state, not the current state"; Xyntra has a dedicated `Reality vs README.md` note classifying every README claim as Aspirational / Partially true / False / Verified; AsteroidsAI's LifeOS flags "five paradigms claimed, four shipped" as the "anti-puffing headline"; Vynapse's docs state "README pitch over-promises by ~9 milestones"; Tectra's vault notes state "vault notes reflect code; README has not been updated". The discipline of separating shipped from designed is itself a portfolio signal.

**Decision archaeology with rejected alternatives.** Design decisions are captured numbered (D1, D2, ...) with alternatives explicitly considered and rationale. NeuroDrive: D1-D23 in the M6 implementation log; Aurix: D17 typed errors via `ApiError` enum; Tessarix: 14 numbered decisions plus a register of "decisions deferred (not yet decided)"; Nyquestro: 13 decisions recorded with rationale, alternatives, and implications; Chrona: 12 decisions each with alternatives + the conditions that would flip the call. Consistent pattern of recording why-not as well as why.

**Cross-disciplinary synthesis.** Projects pull from disparate domains and integrate cleanly. NeuroDrive fuses neuroscience (three-factor plasticity, eligibility traces, biological homeostasis, continual-backprop structural plasticity) with classical RL (PPO, GAE) inside a Bevy game-engine context. Aurix combines Ethereum-archive ingestion + Uniswap V3 math + LP backtesting + multi-asset benchmark series + adaptive-tercile vol-regime classification + Tauri desktop shell in one codebase. Image Browser sits at the intersection of ML inference, multi-encoder retrieval research (RRF), SQLite-WAL performance engineering, JPEG-aware thumbnail pipeline, and desktop UI. Cernio crosses ATS API integration + AI orchestration + grading rubric design + TUI + web UI. The synthesis is the work.

**Self-driven verification (visual + behavioural).** Image Browser's `--profiling` opt-in produces an on-exit Stall Analysis + Resource Trends `report.md` framed as "encode the validation into the runtime; the report is the debugger"; Cernio's `cernio snap` CLI drives headless Chrome and writes per-pane PNGs to `/tmp/cernio-debug/<ts>/` so the agent itself reads them rather than asking the user; Aurix's telemetry hub explicitly replaces screenshot-based diagnostics ("every screenshot is so much heavier than a couple more lines in a json file"). Pattern of building verification into the runtime rather than relying on out-of-band review.

**Solo-contributor master-only workflow with commit-as-checkpoint discipline.** Aurix is explicit: "solo-contributor workflow — master only, no feature branches; Caner is the only contributor; branches add overhead without coordination benefit; commit-as-natural-checkpoint discipline matters more than it would on branch-and-merge." Visible in every other project. Commit messages range across the discipline spectrum (Performance Profiler's 148 commits in three days with bumps-at-session-end versioning vs Zyphos's `"latest changes, dont know what"`); the awareness of when each tradeoff fits is itself a signal.

**Parallel agent orchestration under locked contracts.** Recurring pattern: decompose a substantial surface into N independent units, freeze the interface contracts, dispatch N background agents in parallel against the contracts, integrate results. Performance Profiler's v0.12 (76 atomic tasks across 6 waves, 14 background agents, ~3× speedup) is the strongest example; Tessarix's 44-widget linear-algebra push (7 worktree-isolated agents in one day) is a smaller instance; Open Source Contributions' `scout-issues` skill (9 Opus agents in one Claude turn) applies the pattern to research; populate-from-lifeos (the very skill producing this file) dispatches one per-project subagent per allow-listed project.

**Reading rejection histories before READMEs.** Open Source Contributions discipline: mine a project's closed-not-merged PRs to surface hidden filters before sinking implementation time. tinygrad's `sz.py` tokenised-line-budget filter became visible from reading recent closures (PR #15453 closed at +78 lines with chenyuxyz's "+78 lines is too much"); burn's inlined-backbone-precedent pattern surfaced from reading LPIPS / DISTS / FID / Gram-Matrix merged PRs end-to-end before A-FINE; tract's `models serialized with tract 0.x.y should work with tract 0.x.z where z >= y` golden rule and 0-external-rejection record. The behaviour is upstream of contribution-velocity outcomes.

**Living-system philosophy / no-permanent-state framing.** Cernio explicitly: "the profile evolves... company grades change as the portfolio grows... no evaluation is permanently settled"; skills must never embed profile snapshots; every skill reads `profile/` fresh on every invocation; the `check-integrity` skill compares profile modification dates against `graded_at` timestamps. NeuroDrive: "One Brain, One Lifetime" — no weight resets across episodes or sessions, the same parameters adapt continuously. Image Browser: pipeline-versioned embedding migration (`embedding_pipeline_version` meta migration that wipes legacy rows when bumped) makes the preprocessing-invalidates-embeddings coupling explicit rather than silent.
