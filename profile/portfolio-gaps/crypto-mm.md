# Portfolio Gaps — Crypto MM / DeFi Engineering lane

> Rewritten 2026-06-01 from the canonical grade-jobs Phase 3 batch over 33 graded crypto-mm jobs. Distribution: 10 S / 3 A / 3 B / 7 C / 10 F — the highest S-share of any active lane and the smallest pool in the database, so the signal is dense but the volume is thin. Pinnacle reach is real (B2C2, Cumberland-DRW, GSR, Keyrock, Talos all scored S in London) and the F-band is dominated by structural exclusions (US-located DRW twins, post-grad-excluded Jump intern programmes, TRM analyst seats) rather than role-fit failures, which means the *engineering-relevant* conversion shape of this lane is closer to 13 viable / 10 dead than the raw 33 suggests.

## Open gaps

The pattern across S/A/B/C reasoning concentrates on a small number of recurring missing pieces. Each is named with the specific jobs that flagged it and the specific closure direction.

- **C++ at depth (HFT-grade trading-systems C++).** The single biggest stack blocker in the lane. Wintermute 1115 (C++ Quant Developer) and 1116 (C++ Quant Developer — Options) both downgraded to C explicitly because "C++ is Familiar only per skills.md (Chrona paused ~20.8KB, Tectra dormant ~2.3KB — both small scaffolds); the C++ gap is the #1 lane blocker on 7+ roles in 2026-04-29 batch". Jump Crypto 550 (C++ SWE | Crypto) same pattern — concept-fit strong, C++ stack-fit is the gating constraint. This is the same gap surfaced in hft and is the dominant cross-lane closure target.
- **Production CEX market-making engine experience.** Lane-affinity.md crypto-mm Gaps section names this verbatim: "no production CEX market-making engine experience; no actual exchange-connectivity production code (Coinbase WebSocket integration is single-venue and read-only)". The Talos Trading Connectivity roles (996, 998) flagged the closest-fit case in the entire batch — Nyquestro's venue-WebSocket work is "the strongest concept match in the portfolio" — but still capped on JVM stack-fit and the single-venue, read-only, synthetic-flow shape. B2C2 101 graduate quant-dev cleared because the role's seniority-band absorbed the gap; mid-band roles will not.
- **FIX / SBE / OUCH adapter production code.** Lane-affinity.md: "no FIX adapter, no SBE, no OUCH". Talos Trading Connectivity (996, 998) JD reasoning explicitly mentions "expected stack: Java/Kotlin + FIX adapters + venue API clients" — Caner has zero FIX. Every institutional digital-asset platform reads for this.
- **OMS / SOR production code.** Lane-affinity.md: "no production-shaped order management system (OMS) or smart-order routing (SOR)". GSR 354 reasoning names "pricing engines, OMS, real-time risk" as the GSR stack target; concept-fit is reachable via Nyquestro but production OMS/SOR is the explicit deltas.
- **JVM stack (Java / Kotlin / Scala).** Talos 995, 996, 997, 998 all flagged JVM stack-fit gaps — "Caner has zero JVM, but stack-fit is the tiebreaker" (995); "JVM stack-fit gap... less load-bearing here because the role's substance (venue integration, idempotent state translation, real-time market data) is more important to the team than the language" (996). Cumberland (DRW) 1202 also names "Java/Python systems with Rust adoption" as the platform stack. JVM is not lane-blocking the way C++ is but is a recurring tiebreaker drag.
- **Solidity authoring at depth.** Aurix reads Solidity reference and ports clean-room into Rust; it does not author native Solidity. None of the 33 jobs ranked Solidity as the primary stack but it remains the canonical "DeFi engineer" credential the lane assumes.
- **MEV / mempool / Flashbots experience.** Lane-affinity.md: "no MEV / mempool / Flashbots experience". Aurix is analytics-side, not extraction-side. Less directly flagged in this 33-job batch but structurally absent.
- **Live-trading PnL track record.** Lane-affinity.md crypto-mm Gaps and the GSR / Wintermute / Cumberland S-tier reasoning all implicitly assume this for senior bands; covered at junior bands by portfolio depth but caps the lane ceiling.
- **Options-pricing infrastructure (vol surfaces / skew models / Greeks).** GSR 355 (Systematic Options Researcher) downgraded to C explicitly because "Aurix has selection-bias awareness and LVR work but no options-pricing portfolio"; Wintermute 1116 (C++ Options) layered options on top of the C++ gap. Aurix touches Q64.96 sqrt-price math and V3-concentrated LP IL closed forms (options-adjacent), but no equity-options vol-surface work exists.
- **On-chain settlement / institutional digital-asset rails.** Lane-affinity.md: "no on-chain settlement / institutional digital-asset rails experience (Fireblocks, Anchorage)". Settlement-side B2C2 / Talos reasoning treats this as an implicit assumption.
- **FCA-regulated exchange application surface.** Archax 1267 flagged "regulated digital-asset exchange engineering" — day-1 work would be "application-layer exchange engineering (order entry, balances, regulatory reporting) rather than core matching-engine work". Adjacent but not on the portfolio's central axis.
- **Aurix live-data path currently non-functional.** Lane-affinity.md notes "Live-data path also currently non-functional pending Alchemy key restoration". Restoration is a near-free closure of one demoable gap.

The S-band sits on a remarkably small evidence base — Aurix plus Nyquestro carries almost every S-tier reasoning paragraph in the batch.

- **Aurix is the lane pinnacle anchor and is cited verbatim in S-tier reasoning across the batch.** Lane-affinity.md crypto-mm Pinnacle evidence: clean-room Uniswap V3 mathematics on `num-bigint::BigUint`, per-swap LP simulation with LVR per Milionis-Moallemi-Roughgarden, adaptive-tercile vol-regime classifier, multi-variant capital-allocation verdict, three-tier free-data fallback, 5 chains × 3 protocols, 139 backend tests, "explicitly framed by LifeOS as the crypto-domain hiring project". DRW Cumberland Systematic SE Research 210 reasoning: "per-swap LP simulation with LVR discrete approximation per Milionis-Moallemi-Roughgarden; rebalance rules with explicit recentring + gas-cost accounting; adaptive-tercile vol-regime classifier". GSR 354: "Aurix demonstrating exactly the Q64.96 fixed-point + on-chain decoding concepts GSR's pricing engines need". This is the single most CV-load-bearing artefact in the lane.
- **Nyquestro is the venue-integration anchor.** Cited as "the single best-match role in the batch — Nyquestro's shape and Talos's trading-connectivity team are isomorphic" (Talos 996). Deterministic price-time-priority matching engine, live Coinbase Advanced Trade level2 WebSocket on BTC/ETH/SOL, idempotent L2-to-virtual-order translation via `HashMap<(Symbol, Side, Px), OrderID>`, HDR-histogram p50/p95/p99/p999/p9999/max tail-latency tracking. Nyquestro covers the matching-engine and venue-WebSocket axes in a way the rest of the portfolio cannot.
- **Rust at Proficient across 7+ active projects.** Keyrock 564 reasoning invoked the stack-concentration carveout decisively: "5+ active projects in role's stack... produces ~1.5-letter Q1 offset and Q3 dominant on stack-axis". Cernio + Nyquestro + Aurix + NeuroDrive + Image Browser + Vynapse + Xyntra all active Rust. - **Coinbase Advanced Trade WebSocket integration as the bridge artefact.** Recurring across S-tier reasoning at Talos (995-998), Wintermute (1118), Cumberland (1202) — the live-venue integration evidence is the artefact that makes JD-unavailable reasoning land favourably even with stack mismatches.
- **HDR-histogram tail-latency observability.** Cited at B2C2 101 ("a candidate showing only p9999 because a candidate showing only p50 gets dismissed politely") and Talos 995 ("HFT-style observability / tail latency — Comfortable — Nyquestro"). The hft cross-tag that makes crypto-mm and hft mutually reinforcing on a CV.
- **Statistical rigour (selection bias, Deflated Sharpe acknowledgement, multi-variant verdicts).** DRW 210 / 204 reasoning: "multi-variant capital-allocation verdict defeating single-variant selection-bias readings". Research-engineer bands (Cumberland Systematic Research, DRW FICCO Research) read for this and it differentiates Aurix from a typical LP-backtest pet project.
- **Cernio as the production-shaped multi-layer system spine.** Less directly load-bearing than Aurix/Nyquestro in this lane but recurring in S/A reasoning as the "ship production-shaped systems" credential — DRW 210 cites "Cernio active production data-pipeline".

## Closure prescriptions

Ordered by lane-conversion ROI given the open gaps and the batch's specific feedback. Every prescription names the gap it closes and the specific S/A/B/C jobs that would convert higher with it in place.

1. **Restore Aurix live-data path (Alchemy key).** Near-zero-effort. Lane-affinity.md flags "Live-data path also currently non-functional pending Alchemy key restoration" — a demoable lane-pinnacle artefact in a non-demoable state is a self-inflicted cap. Closes the most embarrassing footnote on the lane's anchor evidence.
2. **Extend Nyquestro to multi-venue read-only feed handler (Coinbase + Binance + OKX).** Closes the "single-venue, read-only" lane-affinity gap directly. Concrete unlock: Talos Trading Connectivity (996, 998) reasoning becomes more decisive; "exchange integration breadth" implicit at GSR, B2C2, Cumberland flips from inferred to demonstrable. Stack-honest — no exchange auth credentials, no order submission, just normalised L2 over an idempotent translator.
3. **Author a small, native Solidity contract (oracle-update mechanism or flash-loan guard).** Closes the "Aurix reads Solidity reference but does not author it" credential gap with a small, scoped artefact. The Aurix DeFi context is the natural surrounding — a contract that the existing analytics could verify against.
4. **C++ project of genuine substance (port one Nyquestro module — e.g. the matching engine core or the HDR-histogram path).** The single highest-leverage closure in the lane and adjacent hft lane combined. Wintermute 1115 + 1116, Jump 550 would all upgrade. Treat as a 4–6 week investment, not a weekend port — the cap right now ("Chrona paused, Tectra dormant — small scaffolds") will not be cleared by another small scaffold.
5. **FIX engine literacy via a minimal QuickFIX adapter or a hand-rolled FIX-4.4 parser.** Closes the "no FIX adapter" lane-affinity gap directly. Talos Trading Connectivity (996, 998) and Cumberland (1202) become materially more credible. Small enough to scope to 1–2 weeks; the credential value is disproportionate to the implementation effort because FIX appears in every institutional-digital-asset JD.
6. **OMS-skeleton extension to Nyquestro.** Order-state lifecycle + venue routing layer above the matching engine. Closes "no production-shaped OMS / SOR" lane-affinity gap. Naturally adjacent to (2) — the multi-venue feed handler and the OMS skeleton can share an order-state model.
7. **MEV / Flashbots literacy artefact (simulated bundle submission, sandwich-detection analytics).** Closes the "no MEV / mempool / Flashbots experience" lane-affinity gap. Lower priority than (1)–(6) because the 33-job batch did not flag MEV as the conversion blocker on any specific job, but it remains a structural lane credential.
8. **Options pricing extension to Aurix (Black-Scholes / SABR / Heston vol surfaces against crypto-options venues).** Closes the GSR 355 / Wintermute 1116 options-pricing gap. Lower priority because options is a specialism sub-lane within crypto-mm; the trader-function version (GSR 355) is auto-downgraded by role-truth-at-hire regardless.
9. **JVM literacy is not worth a dedicated project.** Talos reasoning treats JVM as "tiebreaker drag, less load-bearing because the role's substance is more important than the language". The right investment is the substance projects (Solidity, C++, FIX, OMS) — those compound across the lane; a JVM toy project does not.

## Lane-internal calibration — 33-pool placement

Distribution: **10 S / 3 A / 3 B / 7 C / 10 F**.

- **The 10 S-tier is the densest pinnacle-reach band in the database.** Every S-tier is a London + sponsor-capable + on-axis engineering seat at a recognised crypto-MM brand. Three are duplicates of the same Talos posting under different company-row casings (995↔997, 996↔998 — dedupe at data layer; counts as 2 unique seats, not 4); after dedup, 8 unique S-tier engineering seats across 5 employers (B2C2, Cumberland-DRW × 2, GSR, Keyrock, Talos × 2 unique).
- **The S/A gap is the function-vs-engineering axis.** A-tier (204 DRW Research Engineer FICCO; 1200 Cumberland Trading Ops Engineer; 1229 Kappa Lab Quant Developer) all sit on the engineering ladder but are either (i) research-eng team intake smaller than core SE intake, (ii) "Operations Engineer" mildly off-axis from greenfield engineering, or (iii) JD-unavailable on scope. These are the upgrade candidates if JD detail confirms scope.
- **The B-band sits on stack mismatch, not lane mismatch.** B2C2 102 (Python IT — "IT" prefix dilution), Wintermute 1118 (Python Core Dev — implicit selectivity friction), Archax 1267 (mid-tier exchange — application-layer not core matching engine). These are credibility-builders, not axis bets.
- **The C-band is the prestige-trap band.** GSR 355 (Options Researcher — function fail), Jump Crypto 548 / 550 / 553 (researcher function + C++ stack gap + narrow funnel), Keyrock 563 (Analyst Intern function fail + post-grad cohort filter), Wintermute 1115 / 1116 (C++ pinnacle-selectivity trap). The lane is right; the function, stack, or selectivity is wrong. Worth firing only as cheap-stretch lottery, not budget-priority.
- **The 10 F-band is dominated by structural exclusions, not portfolio fit.** 3 × DRW US-only twins (211, 212), 1 × GSR trader-function (356), 2 × Jump intern post-grad exclusion (549, 554), 3 × TRM analyst-function-plus-US-location triple-F (991, 992, 993), 1 × Wintermute Ventures US/SG investment-function (1121), 1 × Cumberland Quantitative Trader function fail (1203). None of these F-grades reflect engineering-portfolio weakness — they reflect role-function or geographic structural filters.
- **The effective application set after dedup and F-stripping is 13 viable seats over 33 graded jobs (39%) — the highest engineering-relevant conversion shape of any active lane.**

The 33-job pool is small enough that depth matters more than volume. The S-band is essentially the application target; A-band is upgrade candidates pending JD detail; B-band is credibility-builders; C-band is stretch-lottery; F-band is structural exclusions to skip cleanly.
